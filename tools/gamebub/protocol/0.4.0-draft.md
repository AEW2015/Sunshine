# Game Bub fixed-mode protocol decision record — 0.4.0-draft

Status: **host proposal; receiver-agent agreement and wire format pending**.
This revision extends [0.3.0-draft](0.3.0-draft.md) with the requested
lightweight, no-password user experience. Earlier drafts remain unchanged.

## Dedicated mode

The intended experience is a single fixed-profile Game Bub session with video,
audio and gamepad buttons. It should start without a Web UI login, a password
prompt, or an interactive PIN exchange. Remove management UI, tray, and unrelated
client features from the dedicated candidate where practical. Keep the original
installed Sunshine instance and its stock-client behavior intact.

An initial fixed client identity can be provisioned ahead of time. The host can
trust the Game Bub's public certificate; the corresponding private key stays on
that device and is never embedded in the public repository. This eliminates the
user-facing pairing step while retaining a way to recognize the device. Reusing
one hardcoded private key across builds or devices would let anyone possessing
it impersonate the handheld. If the ESP32 team selects a different transport,
agree on the equivalent fixed-device identity and trust procedure instead;
this draft does not prescribe TLS or a packet format for the custom mode.

The exact codec, frame layout, audio format, session handshake, endpoint and
recovery remain subject to the receiver team's agreement. A single explicit
mode/profile identity must reject mismatches; JPEG must never use an H.264
identifier. Passwordless does not imply that control traffic should be accepted
from arbitrary devices: the gamepad can control the host.

## Existing Sunshine pairing option

For a client that actually supports Sunshine's existing certificate-based
GameStream control path, `../seed_pairing.py` can prepare a **new, separate**
state file containing one public client certificate. Sunshine's source loads
`root.uniqueid` and `root.named_devices` from that file and checks the presented
certificate against enabled records. The utility validates X.509 syntax with
OpenSSL through Python's standard library and will not overwrite an existing
file or accept additional private-key material. It does not prove that a
certificate is accepted in a TLS session or that an ESP32 client supports it.

The state file does not disable Sunshine's Web UI or configure its password.
An unconfigured stock Web UI can expose its initial credential-setup flow; it
is not a passwordless dedicated-mode implementation. A future dedicated build
needs its own explicit control over which listeners and UI routes start, along
with input authorization, stock-client compatibility, and receiver tests.

## Slim-build work

Sunshine already provides `SUNSHINE_ENABLE_TRAY=OFF`, which skips its tray and
the tray's Qt dependency path. A candidate release can also omit documentation
and test binaries; build and run tests in a separate test directory first.
Further removal of Web UI, discovery, encoders or dependencies requires tracing
their runtime dependencies and measuring the resulting executable. Those
removals have not been implemented or measured. The host still lacks the MSYS2
UCRT64 toolchain, so no native candidate or size measurement is available yet.
