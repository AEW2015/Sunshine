# Game Bub video-only receiver test — 0.5.0-draft

Status: **experimental trusted-LAN test; no authenticated session or audio**.
This adds the receiver team's [pinned handoff](https://github.com/AEW2015/moonbub/blob/75f8497b6ffefadd8c0403728b93ccfbbfa02f52/docs/sunshine-receiver-handoff.md)
to the earlier [0.4.0 host proposal](0.4.0-draft.md). It is not a final shared
production protocol and does not implement a Sunshine codec extension.

The prototype selects baseline JPEG with 720×480, 8-bit three-component
YCbCr, 4:2:0, one interleaved SOF0 scan, standard fixed Huffman tables and
8-bit quantization tables. It does not support 4:2:2, progressive coding,
optimized Huffman tables, restart intervals or restart markers. The complete
frame limit is 262,144 bytes. The two tested frame-0 fixtures passed the FPGA
RTL test, but physical playback, network throughput, and display timing were
not measured. The receiver also accepts 4:4:4 in its offline profile tests;
the host's single-frame test sender deliberately uses the conservative 4:2:0
subset. Its marker order is restricted to the observed JFIF encoder output.
The receiver centers the 720×480 canvas on its 800×480 mounted panel, leaving
40 black columns on each side. The canvas itself contains the 720×405 16:9
image with 37 top and 38 bottom black rows.

The existing receiver's [MSV1/MSF1 v1 test format](https://github.com/AEW2015/moonbub/blob/75f8497b6ffefadd8c0403728b93ccfbbfa02f52/host/PROTOCOL.md)
uses UDP port 5533, network-byte-order headers, sequential chunks up to 1024
bytes, whole-frame CRC-32 and capture timestamps. The sender's 40-byte MSV1
header and all payload bytes match the receiver's pinned golden fixture. The
sender paces each datagram against the configured MSV1-byte rate and stops an
incomplete frame when its deadline cannot be met. Feedback is parsed only from
the connected UDP peer; its free-byte field is advisory and a received-frame
acknowledgment does not prove decode or presentation. The test protocol has no
authentication and must only be used on the intended trusted test network.

The host also passed a host-process test against the receiver's exact Rust
parser at revision `75f8497`, using the host's frame-0 JPEG that the receiver
team separately tested in FPGA RTL. Valid frame completion, CRC failure,
recovery on a newer SOF and 32-bit frame-ID wrap were checked. A separate
localhost UDP run passed against the receiver's Python reference reassembler.
Neither test exercised the firmware on an ESP32 or the physical FPGA/display.

`../msv1.py` sends one validated fixture and waits for matching frame ID and
capture timestamp in feedback. It does not stream clips or desktop video, send
audio, inject controller input, negotiate Sunshine codecs, or measure display
latency. Earlier `host.py` remains an offline video benchmark. The receiver
repository has a separate experimental clip/desktop test sender. Neither is a
completed Sunshine integration.

The receiver returns the 12-button FPGA mask in feedback. The host translates
this mask into the logical names from 0.3.0, but does not inject any input. Its
format, session handling and authentication need a mutually agreed versioned
extension before use beyond a trusted test environment. Audio and presentation
acknowledgments also need receiver implementation and protocol agreement.
The receiver currently sends changes in its 20 ms socket loop and a 250 ms
heartbeat, with zero on disconnect/network silence; these are implementation
settings, not measurements of physical input latency.
