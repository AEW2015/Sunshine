# Game Bub fixed-mode protocol decision record — 0.3.0-draft

Status: **host proposal; receiver-agent agreement and wire format pending**.
This revision extends [0.2.0-draft](0.2.0-draft.md) with the published Game Bub
hardware controls and a host-side gamepad mapping. Previous drafts remain
unchanged. These internal flags do not define the ESP32 network packet format.

## Confirmed Game Bub inputs

The [Game Bub framework interface](https://docs.gamebub.net/developing-cores/reference-interfaces/#input-input-inputv0)
exposes twelve active-high, synchronized gameplay signals: A, B, X, Y, four
D-pad directions, L, R, Start, and Select. The
[handheld firmware at revision 266edbb](https://github.com/elipsitz/gamebub/blob/266edbbbf615f2279aab8b3ac27ecf1b762b381c/firmware/handheld/src/device/input.rs)
reads those gameplay buttons from an FPGA status register. It reads Home,
volume and power separately. The custom streaming FPGA/ESP32 implementation
must confirm how it will expose and forward these states; the register layout
is not selected as the network format.

## Proposed Windows gamepad mapping

Map each Game Bub face-button name to the same Sunshine/Xbox button name;
map Select to Back and the shoulders to the left/right bumpers. This preserves
button labels, including Game Bub's A for confirm. Xbox-style face buttons are
positioned differently, so the physical position of a PC prompt can differ.

| Game Bub input | Current firmware FPGA status bit | Sunshine digital button | Internal flag |
| --- | --- | --- | ---: |
| Up / Down / Left / Right | 7 / 6 / 5 / 4 | D-pad Up / Down / Left / Right | `0x0001` / `0x0002` / `0x0004` / `0x0008` |
| Start / Select | 1 / 0 | Start / Back | `0x0010` / `0x0020` |
| L / R | 3 / 2 | Left / Right bumper | `0x0100` / `0x0200` |
| A / B / X / Y | 11 / 10 / 9 / 8 | A / B / X / Y | `0x1000` / `0x2000` / `0x4000` / `0x8000` |

These values match `src/platform/common.h` at the Sunshine checkout used here.
The lab function `gamepad_buttons()` maps a complete set of lowercase logical
names to these flags; empty input produces a neutral controller. Combined or
repeated button names are handled without creating extra presses. Home remains
reserved for handheld operation; power and volume remain device controls. No
stick or trigger is synthesized. Games requiring analog sticks or more shoulder
controls may not be playable with the handheld's built-in buttons alone.

Sunshine contains virtual gamepad implementations for Windows, including Xbox
360 support through ViGEmBus and Virtual HID support when available/configured.
No adapter is wired up or tested with an actual Game Bub yet. On the inspected
host, no ViGEmBus service was found; Virtual HID availability was not confirmed.
Do not install or change a driver on the working Sunshine instance as part of
receiver tests. The candidate must fail clearly if its chosen backend is absent.

The receiver team must still agree the snapshot cadence, sequence/wrap, session
identity and timeout, and how the ESP32 accesses FPGA button states. Forward
only accepted current-session snapshots; neutralize the virtual controller when
the session ends, times out, or the adapter fails. No keyboard injection is
required for the dedicated controller path.

## Audio hardware reference

The [Game Bub framework audio interface](https://docs.gamebub.net/developing-cores/reference-interfaces/#audio-audio-audiov0)
documents 48 kHz left and right signed 16-bit PCM samples at the FPGA core
interface. This is useful for the receiver-side design; it does not select a
Wi-Fi audio codec, packet size, endianness, or prove the custom streaming core
implements that interface. Those still require agreement and receiver tests.
