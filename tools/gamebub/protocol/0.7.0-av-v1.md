## Wire alignment implemented on Windows

`av_protocol.py` implements the fixed48-byte big-endian header and checks the
full datagram, including payload, using IEEE CRC32 with bytes40..43 zeroed.
Version1,48-byte header, nominal48293Hz, zero reserved field, exact lengths,
class/type, flags, payload schemas and ADPCM headers are validated. Maximum
datagram size is560 bytes. The golden HELLO, OFFER, START, KEEPALIVE, audio,
MSI1 and STOP datagrams match exactly, including their published SHA-256 values.
Fixtures are preserved locally with source hashes under `fixtures/av-v1/`.

| Offset | Width | Meaning |
| --- | --- | --- |
| 0 | 4 | Class magic MSC1/MSR1/MSA1/MSI1 |
| 4 / 5 | 1 / 1 | Version / per-class type |
| 6 | 2 | Header length48 |
| 8 | 8 | Nonzero64-bit nonce for HELLO; otherwise session cookie |
| 16 | 4 | Independent per-class wrapping sequence |
| 20 | 4 | Rate48293 |
| 24 / 26 | 2 / 2 | Sample frames505 for audio, zero otherwise / payload length |
| 28 | 4 | Audio-enable bit for HELLO/OFFER/START; zero otherwise |
| 32 | 8 | Diagnostic monotonic microseconds |
| 40 / 44 | 4 / 4 | Whole-packet CRC32 / zero reserved |

Video UDP5533 and its MSV1/MSF1 remain separate. AV targets UDP5534 from one
bound socket; the future socket runner must pin exact source/peer endpoints.
CRC and cookies do not authenticate the peer.

## Session and input alignment

`av_session.py` provides a transport-independent host state adapter:

- A random nonzero64-bit host nonce identifies HELLO0. Only an OFFER from the
  pinned peer with matching echoed nonce and flags is accepted. START1 echoes
  the nonce and cookie; a matching ACTIVE MSI1 confirms activation.
- START receipt retries preserve cookie and sequence spaces. Locally expired
  offers require a fresh session. KEEPALIVE is scheduled at100ms intervals,
  beginning at control sequence2; STOP uses the next control sequence.
- Audio starts at sequence0. Allocate an MSA1 sequence for every encoded block
  before queue discard so dropped blocks leave sequence gaps. No retransmission
  or implicit codec substitution is implemented.
- MSI1 uses its own wrapping sequence, independently of video/audio/control.
  Wrong peer/cookie, duplicate, older or ambiguous half-range sequences cannot
  refresh input. Input neutralizes at500ms without newer MSI1; a newer snapshot
  may recover within the same still-live session. Shutdown/driver error releases
  controls. MSF1 remains diagnostic and does not inject input.
- MSI1's eight u32 fields preserve the published button/counter/state layout.
  Queued/played/underrun fields are exposed as unavailable when snapshot-valid
  is clear. Rejected/unconfirmed admission is not a claim of physical rejection.
  AUDIO_ENABLED identifies the negotiated mode and may remain set after a feeder
  fault; it is not playback readiness or health evidence.

The generic `OrderedInput` helper still accepts a local16-byte token, but AV v1
maps the64-bit cookie into that token internally and overrides its timeout to
500ms. No16-byte token or250ms timeout is transmitted or used as the AV contract.

These classes do not yet implement a live socket loop, bounded audio queue or
combined video/audio scheduler. A caller must tick timeout, send keepalives,
enforce endpoint binding, and close socket/controller resources even on errors.
Unit state tests are not proof of receiver lease behavior or two-host operation.

## Resolved audio oracle discrepancy

The initial packet checks passed but the FFmpeg-based PCM comparison failed.
The published block's decoded reference hash is
`85459adb008cf8af659afb72f6f03823940f1393bbc92a39840b9adfd62a81cc`.
The host's PyAV18.1.0/libavcodec62.28.102 produces
`c6191e79a2eb34911f4d9d076332761bff2c2e9621f16aab8a8cc94611167212`.
Decoding the original published WAV and the local WAV wrapper gives the same
host result, excluding the wrapper as the observed cause.

An isolated mathematical comparison reproduces the published PCM exactly using
`diff = ((2 * magnitude + 1) * step) >> 3`. The shift/add form reproduces the
host PCM exactly. First nonzero stereo samples are13/-13 in the reference versus
11/-11 locally;985 of1010 scalar samples differ, with maximum absolute difference17.
No fixture was modified. The receiver agent confirmed that full-product
rounding is normative and made the rule explicit in `aab1ba3`.

`audio_codec.py` now implements explicit product-rounded encoding and decoding;
PyAV remains responsible for source resampling only. Every encoder predictor
update uses the same product before applying sign, clamping and updating the
step index. A fixed three-frame regression proves that shift/add feedback would
select a different next code. Blocks retain their own predictor/index headers.

`verify_av_vectors.py` now reports `wire_match=true`, `pcm_match=true` and
`complete_conformance=true`, returning zero. Its decoded output is exactly2020
bytes and matches the required hash above, including the13/-13 second frame.
Prior failure JSON/PCM evidence remains intact. New version2 deterministic
fixtures record `gamebub-ima-product-v1` and preserve the earlier version1 assets.
No audible playback, physical controller, live handshake or A/V sync is claimed.
